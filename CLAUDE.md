## What this is

`allergy-friendly-travel.com` — a Vite/React SPA (Netlify-hosted), Supabase
backend (Postgres + Edge Functions), content generated by a daily
`content-pipeline` job and cross-posted to Facebook/Instagram/Pinterest.
Helps travelers with food allergies find hotels/restaurants with real
evidence of allergy accommodation from Google reviews and Tripadvisor.

Supabase project id: `embuxlxugjkjgsusrmlx`.

## Non-negotiable policies (violating these has already caused real problems)

- **Never fabricate content.** No invented reviews, quotes, or testimonials
  attributed to guests who don't exist — this exact mistake shipped once
  (hardcoded "customer quotes" in `TopHotelsSection.tsx`) and had to be
  ripped out. Every review/quote shown on the site must trace to a real
  source (Google review snippet via `content-pipeline`, or a real
  Tripadvisor review via `tripadvisor-reviews`).
- **Hard cost ceilings, enforced in our own code, never trust a
  third-party "expected cost" UI.** Google Places (`hotel-search`,
  `restaurants-search`): ₪100/month, calibrated from a real GCP invoice
  (`COST_PER_CALL_ILS` in both functions). Tripadvisor (`tripadvisor-reviews`):
  ₪50/month, list-price estimate (not yet invoice-calibrated — check
  Tripadvisor's Billing page periodically and recalibrate
  `TRIPADVISOR_COST_PER_CALL_ILS` the same way Google's was). Both guards
  fail *closed* (block the live call) if spend can't be verified. Never
  raise a ceiling without telling the user first — this has been litigated
  extensively in this project's history.
- **Every new table needs RLS enabled at creation time**, not after the
  fact — `tripadvisor_cache` shipped without it and sat publicly
  writable/deletable for days until Supabase's own security advisor caught
  it. Run `get_advisors(type: "security")` after any schema change.
- **Trailing slash on every internal URL.** The host 301-redirects every
  non-root path to add a trailing slash (prerender writes
  `dist/<route>/index.html`), so every canonical tag, sitemap entry,
  JSON-LD url, and internal `<Link>` must include one — see
  `src/utils/seo.ts`'s `buildCanonical()`. `npm run verify-seo` (wired into
  the Netlify build after prerender) fails the build if any prerendered
  page's canonical doesn't match its real location — this is a real,
  proven guard (already caught one regression in production).

## Where things live

- **Edge Functions** (`supabase/functions/*`): `hotel-search`,
  `restaurants-search` (Google Places, budget-gated), `tripadvisor-reviews`
  (Tripadvisor Terra API, cached permanently per place, budget-gated),
  `content-pipeline` (daily article generation + FB/IG/Pinterest posting on
  publish), `social-poster` (FB/IG daily — newest article only, no
  backlog), `pinterest-poster` (daily backlog sweep — Pinterest is
  deliberately different from FB/IG here). **Currently blocked**: Pinterest
  real pin creation needs Standard API access (Trial tier blocks
  production pins) — pending the user submitting Pinterest's app-review
  form with a demo video.
- **Secrets**: Supabase Edge Function secrets (dashboard → Edge Functions →
  Secrets) — `GOOGLE_MAPS_API_KEY`, `TRIPADVISOR_API_KEY`,
  `PINTEREST_CLIENT_ID`/`SECRET`/`BOARD_ID`, `CRON_SHARED_SECRET`. No MCP
  tool can set these directly — ask the user to add them via the dashboard.
- **Governance docs**: `TASKS.md` (checkbox tasks, each with
  RATIONALE/HOW-TO/DoD), `CHANGELOG.md` (dated entries) — update both
  alongside any real change, per `.github/pull_request_template.md`.

## Known gaps / things Claude cannot check on its own

- **No Google Search Console API access** — GSC data only arrives via
  screenshots the user pastes. Don't claim to have checked GSC unless the
  user just shared it.
- **No Pinterest dashboard access** — can't check Standard-access approval
  status programmatically; ask the user.
- This sandbox's `npm run build` fails on a pre-existing, sandbox-only
  issue (missing `@lovable.dev/mcp-js`) unrelated to any real code change —
  confirmed via `git stash` repeatedly. Real validation happens on
  Netlify's own build (watch the PR's CI).
- Direct `WebFetch`/`curl` to the site's own domain, Supabase, and most
  third-party dashboards (Netlify, Pinterest, etc.) are blocked by this
  environment's egress proxy. Workaround used throughout this project: the
  Postgres `http` extension (enabled on this project) via `execute_sql`,
  which has unrestricted network access — e.g.
  `select status, content from http_get('https://www.allergy-free-travel.com/...')`.

## Recurring automation

A weekly Routine (self-bound to the session that set it up, not a fresh
session per firing) checks Supabase security/performance advisors, this
month's Google/Tripadvisor budget usage, a live spot-check of a few
canonical URLs, and recent `pipeline_log` failures — report-only, no
autonomous deploys or spend changes. See `list_triggers` for its current
schedule.
